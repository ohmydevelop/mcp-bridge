# 运维与回滚

- `GET /healthz` 检查数据库可用性。`bridge_get_status` 返回积压和失败数；其 recent_changes 可查看修改及游标缺口。数据库和事件历史会随使用增长，应监测数据卷空间。
- 冷备份时停止常驻进程，复制整个私有状态目录，包括 SQLite、`scripts/`、包快照和实例数据。单独保管主密钥及环境凭证。恢复时把副本放入权限 0700 的空目录，使用同一主密钥与原上游配置启动；进程将重建 socket，并继续处理待投递记录。避免让旧实例和恢复实例同时向同一自动化端点投递。
- 使用 `bridge_update_source` 传入 package_path、patch 和当前 revision 安装新版插件。回滚时绑定此前保留的 digest。若新连接探测失败，已有实例继续服务。外部 CLI 及其依赖需在服务账户环境中可执行。
- Agent 添加的 stdio 程序拥有服务账户的操作系统权限。系统服务模板使用独立账户。HTTP token、主密钥、目标 origin 和网络暴露范围属于部署边界，不能通过普通 Agent 的 MCP tool 修改。

## 编排脚本的存储和恢复

`bridge_save_tool` 把已发布的 Python 源码保存到私有状态目录的 `scripts/<sha256>.py`。该文件是明文快照，默认 Unix 文件权限为 0600，Windows 使用私有状态目录的 ACL。SQLite 保存工具定义、版本、依赖和摘要。两个版本的源码相同时共用一份快照。继续通过工具发布修改；直接改写快照会导致摘要校验失败。一次性执行和预览不会创建源码快照。CLI 目标使用的外部脚本和业务输出仍在原路径，由使用者负责备份。

升级前先停止服务并备份整个状态目录。首次启动会将当前及历史定义迁到文件中，保留原版本号。升级后回退到旧二进制需同时恢复升级前的状态目录。启动时校验全部保留的快照，执行时再次校验；缺少文件或内容损坏时从同一备份恢复。

旧版从被新版替换或被取消发布起保留至少 30 天，迁移来的历史版本从升级时起计时。回收任务在启动时及之后每小时运行。触发器（包括暂停的触发器）和保留的运行记录固定的版本继续保留。只有全部版本引用释放后才删除源码文件。
